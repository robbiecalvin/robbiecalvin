WordPress Maintenance / Checklist

WordPress maintenance checklist

Before updating WordPress, confirm you can restore the site, test the planned changes on staging, and write down the workflows you’ll check afterward. Use this checklist for a maintenance visit or handoff.

Before the update

  • Write down the starting versions. Record WordPress, PHP, the active theme, and plugins involved in this update. Check release notes for compatibility requirements and database changes. Plan the update order around those dependencies.
  • Confirm the backup and restore procedure. Make sure the backup includes files and the database. Note when it was taken, where it’s stored, and who can restore it. On a critical site, test the restore with an isolated copy.
  • Identify the pages that matter. Open the homepage, a representative interior page, and any form or store workflow you’re responsible for. Record anything already broken so it can be distinguished from a new issue.

Reference the official WordPress guides for updates and compatibility and file and database backups.

Test the updates on staging

Use a staging copy that reflects the live theme, plugins, PHP version, and relevant settings. Keep test submissions, payment activity, and notification emails away from real visitors and customers.

  • Apply the planned updates and check for warnings or required database updates.
  • Check the same pages and workflows on a phone-sized screen and a desktop screen.
  • For a WooCommerce store, use test mode to check a product, cart totals, and checkout. Record anything affected by caching, shipping, or taxes that the site relies on.
  • Write down each change and its result. Resolve unexpected failures before scheduling the live update.

WooCommerce documents staging and backup considerations in its update guide.

Repeat the checks after the live update

  1. Take or confirm a fresh backup before applying updates during the agreed maintenance window.
  2. Apply the verified changes and clear the relevant caches. Open the live site in a fresh browser session and repeat the agreed checks.
  3. If a critical workflow breaks, pause further changes and use the agreed rollback plan. For an active WooCommerce store, account for orders or other changes recorded since the backup before restoring a database.
  4. Record the final versions, what passed, any deferred items, and who owns the next step.

What to record after a maintenance visit

Changes
Component, previous version, updated version, and reason.
Checks
Page or workflow, result, and any evidence link.
Follow-up
Open issue, priority, and the next person responsible.
